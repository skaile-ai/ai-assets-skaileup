# _concept/02_grounding/findings/brief-seeds.md

What the repository's own documents say about the product: pitch, audience, problem, hero flow,
roadmap, constraints and the products named as comparables. `concept-brief` seeds its draft
from this and shows each graded value as a proposal; none of it is a decision yet. Motivation
and audience are what source code never states, so a thin README yields thin seeds.

## Format

Frontmatter per `tree/02_grounding/findings/README.md`; the body has one section each for pitch,
audience, problem, hero flow, roadmap, constraints and comparables, every value graded.

## Writing it

1. Read the README, the manifest's `name`, `description`, `keywords` and `homepage`, the changelog
   and `docs/`.
2. Take comparables from the products named under "similar to", "inspired by" or
   "alternatives".
3. Mark a value `needs_review` when the docs are thin; never fill a gap with something inferred
   from the code.

## Checks

Every value is graded and cites the file that backs it.
