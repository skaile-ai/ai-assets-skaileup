# Layout pattern sources

External places to study app layouts — design-system floorplans, galleries of shipped apps, agent skills, and code you can run — sorted by mobile vs desktop and simple vs data-heavy. It is a maintainer's aid next to [floorplan-exemplars.md](./floorplan-exemplars.md), which lists the in-house references; this file covers what lies outside `~/devBench/`. It is not part of a shipped asset, and no skill reads it.

Every source was opened on 2026-10-21 unless its row says otherwise; `[INFERENCE]` marks a reading not stated by the source, and `[not opened]` marks a row that rests on metadata only. Prices and counts are the sites' own figures on that date.

### Agent skills and agent access

- Only two skill sets carry **layout-level** rules: [dembrandt/dembrandt-skills](https://github.com/dembrandt/dembrandt-skills) (one skill per layout topic: app shell, layout paradigms, guided paths, responsive paradigms, operational expert tools) and [educlopez/ui-craft](https://github.com/educlopez/ui-craft) (ASCII dashboard recipes, forms, responsive). The large ones — `anthropics/skills` `frontend-design`, `ui-ux-pro-max`, Vercel's `web-design-guidelines` — cover visual direction or review checklists, not floorplans.
- Mobbin, Refero and Nicelydone expose an **MCP server** (paid plans), so an agent can query real-app screens by page type. Cheapest coverage of all five gaps: Refero Pro ($120/yr) plus SaaS Interface ($39 once); add Mobbin Pro ($120/yr) for Android and mobile flows.
- Skip: Pttrns (now a blog), Land-book, Godly, Collect UI, Dribbble (marketing pages or concept work), Baymard (e-commerce only).

## 1. Design systems and official guidelines

**Fetch quirks worth knowing**
- SAP Fiori: only **version-pinned** URLs (`/v1-136/…`, `/v1-148/…`) with a trailing `/usage` fetched for me. The unversioned URLs that search engines return gave 404. Pin a version when you link.
- m3.material.io is a JS app: static fetch returns an empty shell. All M3 URLs below were confirmed in headless Chromium.
- Polaris React site (`polaris-react.shopify.com`) refused connections. `polaris.shopify.com/patterns` now redirects to `https://shopify.dev/docs/api/polaris`. Polaris React's repo is `Shopify/polaris-react-archive`, so the docs and code moved to shopify.dev.

### Cross-cutting responsive rules found (usable as rulebook defaults)

- Two-pane layouts collapse to one pane below roughly 840 dp / 1024 px: M3 and Android window size classes (compact < 600, medium 600–840); SLDS master-detail needs 1024 px+; Atlassian panel overlays at ≤ 1024 px; Fiori FCL shows one column at size S. ([Android](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes), [SLDS](https://www.lightningdesignsystem.com/2e1ef8501/p/33e9af-layout), [Atlassian](https://atlassian.design/components/navigation-system/layout/usage), [Fiori FCL](https://www.sap.com/design-system/fiori-design-web/v1-136/page-types/page-layouts/flexible-column-layout/usage))
- Supporting pane proportions: 70/30 at expanded, 50/50 at medium, below/bottom-sheet at compact ([Android canonical layouts](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts)). SLDS record sidebar is 1/3 with a 400 px minimum.
- Data tables are not mobile floorplans: Fiori excludes grid/analytical/tree tables on phones and says build a separate reduced app ([worklist](https://www.sap.com/design-system/fiori-design-web/v1-136/page-types/floorplans/work-list/usage)). Apple says keep functionality the same across size classes and swap tab bar ↔ sidebar ([Layout](https://developer.apple.com/design/human-interface-guidelines/layout)).
- Wizard: Fiori limits to 3–8 steps and advises against it for 2-step or familiar tasks ([wizard](https://www.sap.com/design-system/fiori-design-web/v1-136/ui-elements/wizard/usage)); Cloudscape and Carbon each document a single-page alternative.
- Do not change information density inside one page ([Shopify layout](https://shopify.dev/docs/apps/design/layout)).
