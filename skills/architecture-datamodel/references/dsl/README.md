# Data-model DSL

`architecture-datamodel` copies these files into a project's `_concept/10_blueprint/datamodel/`, together with `datamodel-model.schema.json` and `datamodel-seed.schema.json` from the collection's `tree/10_blueprint/datamodel/`. Never edit the copies; both files start with `// skaile-model <version>`, and a copy with another version is replaced.

| File | Role |
|---|---|
| `skaile-model.ts` | The DSL: `entity`, `f.*`, `sharedEnum`, `defineModel`, `scenarios`, types `Infer`, `Model`, `Seed`. No dependency, no Node API, so the mockup package imports it too. |
| `gen.ts` | Runs `model.ts` and `seed.ts`, validates, writes `model.json`, `model.dbml`, `seed.json`. Node only. |

## What is authored, what is generated

| Authored (edit these) | Generated by `gen.ts` (never edit) |
|---|---|
| `model.ts` — entities, fields, enums, relations, proposals | `model.json` — the interchange file for `build-database`, tests and the editor canvas; its `editor` key is carried over from the existing file |
| `seed.ts` — scenarios typed against the model | `seed.json` |
| | `model.dbml` — confirmed entities only; proposed ones are named in a header comment |

The authoring layout, the `f.*` vocabulary and the proposal marker are in `tree/10_blueprint/datamodel/model.md § Format`; the seed rules are in `tree/10_blueprint/datamodel/seed.md § Format`.

## Run

```sh
npx tsx _concept/10_blueprint/datamodel/gen.ts        # or: cd into the directory and run npx tsx gen.ts
npx -y -p typescript@5 tsc --noEmit --strict --target es2022 --module esnext --moduleResolution bundler model.ts seed.ts
```

`gen.ts` writes nothing unless everything passes. A violation exits 1 with one `file: $.json.path: message` line each:

- `model.ts`: an entity id that is not PascalCase of its `glossary` id, a `label_field` or `key_field` that names no field, an `m2o` name without `_id`, a relation target or shared enum missing from `defineModel`, an `m2m` junction without an `m2o` to both sides, an unreferenced shared enum.
- `model.json` and `seed.json` against the two schemas; the message ends with the schema pointer (`datamodel-model.schema.json#/$defs/snakeName/pattern`). A schema keyword the built-in validator does not implement stops the run.
- `seed.ts`: an unknown entity key, a field the entity does not have, a missing required field, a wrong scalar type, an undeclared enum value, a relation id that is not a row of the target in the same scenario, a duplicate row id.

`tsc` catches the same field mistakes at edit time (`Object literal may only specify known properties`), which is why `seed.ts` stays TypeScript: an imported `seed.json` would never raise that error.

## Tests

`bash skills/architecture-datamodel/tests/run_gen.sh` copies the tool files and schemas into a temp directory per case and checks the generated files against `tests/expected/` byte for byte, the `editor` carry-over, the `tsc` error for a misspelled seed field and the non-zero exits.
