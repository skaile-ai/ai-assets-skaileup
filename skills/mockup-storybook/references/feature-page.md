# Feature pages — a worked example

One feature, `polls/draw-pick`, from the demo project Lunch Roulette. The page is `Features/polls/draw-pick` (story id `features-polls-draw-pick--overview`), rendered by `src/components/FeatureDoc.vue` from `src/generated/concept.json`. The node is `tree/09_mockup/storybook/README.md § Feature pages`; the spec it reads is `tree/05_features/[featureset]/[feature].md § Format`.

## What the page shows

Each block comes from one file under `_concept/`, and a block whose source is empty is left out.

| Block | Source | draw-pick |
|---|---|---|
| header: featureset, slug, priority | the spec's path and `priority:` | `polls`, `draw-pick`, `must-have` |
| lead paragraph (outcome) | the `outcome` column of `05_features/featuresets.md` | a closed Poll names its Pick and a tie is settled by a visible Draw |
| Why | `## Framing` of `08_dossiers/draw-pick/index.md` | The product is named after this feature. A tie among the most-voted Places is common in a team of five to ten, and a second round of voting is what the chat thread does today. |
| Featureset | the line under `## polls` in the roster | An organizer opens a lunch poll, members vote for places and the app settles on a pick. |
| Who may do what | `permissions:` | organizer: read, update; member: read |
| Scope | the bullets under `## Scope` | `IN: at the deadline the Poll closes and the Place with the most Votes becomes the Pick.` and four more |
| Acceptance criteria | the spec's `AC-…` bullets, with the EARS text of `04_journeys/stories.yaml` below each | `AC-run_a_lunch_poll-03` the most voted place becomes the pick — WHEN the deadline of an open poll passes, THE SYSTEM SHALL close the poll and show the place with the most votes as the pick. |
| Screens | the spec's `screens:` plus every `07_screens/*.md` whose `implements:` names the spec; a link when `src/screens/<id>.stories.ts` exists | `poll` (Poll), linked to `Screens/poll` |
| Journeys | `story_refs:`, with title and stage from `stories.yaml`; a link when the journey is not `backlog` and `src/journeys/<id>.stories.ts` exists | `run_a_lunch_poll` Run a lunch poll from opening to pick, `hero`, no story yet |

The same join runs the other way: `screenDocs('poll')` puts the Poll purpose ("Vote for a place, watch the counts and see the pick. …") and an **Implements** list on `Screens/poll`'s Docs page, naming `polls/create-poll` (proposed), `polls/draw-pick` and `polls/vote-on-place`.

## The story

`src/features/polls/draw-pick.stories.ts`, written by `scripts/gen-concept.ts`:

```ts
// Generated by scripts/gen-concept.ts from _concept/05_features/polls/draw-pick.md; edit the spec, never this file.
import type { Meta, StoryObj } from '@storybook/vue3-vite'
import FeatureDoc from '../../components/FeatureDoc.vue'

const meta = {
  title: "Features/polls/draw-pick",
  component: FeatureDoc,
  args: { spec: "05_features/polls/draw-pick.md" },
} satisfies Meta<typeof FeatureDoc>

export default meta

export const Overview: StoryObj<typeof meta> = {}
```

## Nothing here is hand-written

The story file, `concept.json` and the page are regenerated on every start and on a change to `05_features/`, `07_screens/`, `08_dossiers/` or `04_journeys/stories.yaml` while `storybook dev` runs, and all of it is gitignored. To change what the page says, change the spec, the roster, the dossier or the journey; a note left on the page routes to `05_features/polls/draw-pick.md`.
